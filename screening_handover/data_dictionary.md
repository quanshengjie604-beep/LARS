# Screening Handover — Data Dictionary

Generated by the `vcbrain` pipeline. This file documents the custom fields,
collection rules, and point-in-time semantics for the delivered JSONL files.

## Provenance & scope

- **Seed source:** Y Combinator public company directory (via the `yc-oss/api`
  static mirror). YC is the first-class "accelerator directory" seed; the seed
  layer (`vcbrain/sources/yc.py`) is source-agnostic so other accelerators can
  be added identically.
- **Enrichment sources:** GitHub REST API (open-source footprint/activity),
  Hacker News Algolia Search API (public footprint), Product Hunt GraphQL
  (optional, token-gated), and an optional LLM estimator (Anthropic, token-gated)
  for `tam_usd` and soft rubrics only.
- **Age cap:** every company is at most 10 years old (founded on/after
  2016, using YC batch year as the founding proxy). Older companies are
  dropped at seed time. Cohort size this run: 5128. Observation anchor
  ("today"): 2026-07-18. Mode: both.

## Files

| File | One line = |
|---|---|
| `training_features.jsonl` | One historical (batch-era) point-in-time snapshot |
| `training_outcomes.jsonl` | Outcomes after that snapshot (from YC status) |
| `inference_requests.jsonl` | One company evaluated as of 2026-07-18 |
| `evidence_registry.jsonl` | One source document / evidence item |

## Point-in-time strategy (leakage control, requirements §10.1)

- **Inference** records use `observation_date = data_cutoff_date = 2026-07-18` with
  live signals (current team size, current GitHub stars, all HN mentions).
- **Training** records anchor `observation_date = data_cutoff_date` at the YC
  **batch date**. Signals are filtered to `<= cutoff`:
  - GitHub repos created after the cutoff are dropped; live star/follower counts
    (not historically reconstructable) are **nulled** for training snapshots.
  - HN mentions are filtered by `created_at <= cutoff`.
  - `team_size` is nulled for training (current headcount is not knowable at the
    batch date); `current_stage` is set to `seed` (YC program participation) and
    `last_round_date` to the batch date (a real, dated funding event).
  - The LLM estimator is disabled for training snapshots (updated public text can
    reveal later success).

## Custom / derived fields

All derived scores carry `verification_status: estimated` and a formula note in
`evidence_registry.jsonl` (requirements §10.5 — no silent estimation). Null
inputs are dropped from each weighted average and the remaining weights are
renormalised (plan §5): a missing input widens uncertainty, it never scores 0.

| Field | Definition (plan §) |
|---|---|
| `screening.founder_score_persistent` | §5.1 persistent founder score (cold-start: mostly public-footprint + network) |
| `screening.founder_axis` | §5.2 per-opportunity founder axis |
| `screening.market_axis` | §5.3 `{bull,neutral,bear}` from continuous `m` |
| `screening.idea_vs_market` | §5.4 idea-vs-market |
| `*_trend` | §5.5 trend vs the same startup's prior (batch-era) snapshot; `unknown` when no prior |
| `team.open_source_activity_score` | §5.6 from GitHub stars/forks/repos/freshness |
| `team.proprietary_score` | §5.6 `0.4*sat(patents,5)+0.3*oss+0.3*rubric` (renorm; patents usually null) |
| `market.competitor_density` | §5.6 `sat(n_companies_in_category, 50)` over the cohort |
| `market.funding_climate_index` | §5.6 sector deals this quarter / trailing-8q peak (YC batch cadence proxy) |
| `cold_start.public_footprint_score` | §5.6 GitHub followers + HN/PH mentions (low confidence by mandate §4.6) |
| `cold_start.network_centrality` | §6 normalised degree centrality in the YC sourcing graph (shared batch/category) |
| `cold_start.soft_skill_estimate` | §5.6 LLM rubric over public text (low confidence; null without LLM) |

## Known nulls (honest limitations)

Private KPIs are not available from these public sources and are correctly left
`null` (never fabricated, requirements §10.3): `arr_usd`, `revenue_growth_rate_yoy`,
`customer_count`, `churn_rate_annual`, `burn_rate_usd_monthly`, `runway_months`,
`cash_balance_usd`, `patent_count`, and founder track-record fields
(`founder_prior_exits`, `founder_prior_startups`, `single_founder_flag`,
`technical_founder_flag`, `founder_industry_experience_years`). These appear in
each record's `missing_fields`.

## Outcome labels (`training_outcomes.jsonl`, requirements §5)

Derived from the YC directory `status` collected as of the observation-end date
(2026-07-18), which is post-cutoff (allowed for outcomes):

- `status = Public`    -> `exit.exit_type = ipo`, `exit_verified = true`.
- `status = Acquired`  -> `exit.exit_type = acquisition`, `exit_verified = true`.
- `status = Inactive`  -> `failure.failure_observed = true`,
  `failure_definition = shutdown_confirmed` (YC's curated status is a stronger
  signal than a dead website, requirements §5.3), `company_still_observed = false`.
- `status = Active`    -> censored: no exit, `company_still_observed = true`.

Limitations preserved honestly: exact exit/failure **dates** are not available in
the free directory, so the survival-timing labels (`next_event`, timing of exits)
are treated as **right-censored** (`time_*_days` measured to
`outcome_observation_end_date`); the exit *type* is still recorded with its
verification flag. `next_round` follow-on rounds are not observable from this seed
and are censored (`progressed_within_24_months = null`). `growth` (M4) requires two
comparable revenue points, which are unavailable -> `growth = null`,
`m4_included = false` (records explicitly excluded from the M4 subset per §5.4).

This preserves class balance (winners, failures, censored still-alive) as
required by §10.2.
